# Books — Textbook Knowledge Base

This folder stores full textbook XML content (canonical v2 schema) for agent use during
solution generation, question drafting, and curriculum analysis.

## Structure

```
books/
  {book-slug}/
    INDEX.md                        # ← READ THIS FIRST: TOC with section codes, titles, exercise ranges
    atoms.json                      # knowledge atom index (definitions, theorems, procedures, examples)
    ch01.xml                        # full chapter 1 (all units combined)
    ch01_unit_01.xml                # unit 1.1 content only
    ch01_unit_01_exercises.xml      # exercises for unit 1.1
    ch01_unit_02.xml
    ch01_unit_02_exercises.xml
    ...
```

## Canonical v2 XML schema

All books use the same unified tag set regardless of publisher.

**Root element:** `<section>` (no attributes)

**Key tags:**

| Group | Tags |
|-------|------|
| Structure | `<heading level="1..4">`, `<paragraph>` (`math="block"` for display math) |
| Knowledge | `<note type="..." source_type="..." title="...">` |
| Examples | `<example number="N" title="...">` → `<problem>` / `<solution>` |
| Exercises | `<exercises>` → `<exercise number="N">` → `<problem>` / `<solution>` |
| Lists | `<list type="ordered|unordered">` → `<item>` |
| Figures | `<figure>` → `<image alt="...">` + `<caption>` |

**Note types (knowledge-bearing):** `definition`, `theorem`, `theorem_key`, `procedure`,
`rule`, `key_concept`

**Note types (non-knowledge):** `practice`, `sidebar`, `caution`, `warning`, `margin_note`

**Math:** All formulas are inline `$$LaTeX$$` directly in text — no wrapping `<math>` tags.

## atoms.json — Knowledge Atom Index

Each book has an `atoms.json` file containing extracted knowledge atoms: every definition,
theorem, procedure, rule, key concept, and worked example from the textbook, indexed for
BM25 search.

Generated by: `python scripts/extract_atoms.py --all-books`

Used by: `scripts/retrieval.py` for prerequisite search during solution generation.

## How to sync books

Books are synced from the book-preparation pipeline:

```bash
python scripts/sync_books.py              # sync all 13 books
python scripts/sync_books.py --dry-run    # preview without changes
python scripts/sync_books.py --book applied-calculus  # sync one book
```

This copies canonical v2 XML from `book-preparation/output/` and regenerates rich INDEX.md files.

## How the agent uses this folder

### Step 1 — Read INDEX.md first

Always start with INDEX.md to understand the book structure and locate the right file:

```bash
cat "books/applied-calculus/INDEX.md"
```

INDEX.md contains:
- The full table of contents (chapter → unit → title)
- Exercise ranges per unit
- Grep examples for common search patterns

### Step 2 — Open or grep the target file

After identifying the right file from INDEX.md:

```bash
# Find a specific exercise
grep -n 'number="25"' "books/applied-calculus/ch04_unit_02_exercises.xml"

# Find an example
grep -n '<example' "books/applied-calculus/ch04_unit_02.xml"

# Find a term
grep -in "chain rule" "books/applied-calculus/ch03_unit_03.xml"

# Find all definitions in a unit
grep -n '<note type="definition"' "books/applied-calculus/ch04_unit_01.xml"
```

### Step 3 — Inline referenced content

When a target exercise says "Let f(x) be as defined in Exercise 15", use the above to
find Exercise 15 and inline it into the source brief's `context_dependency.imported_content`.

## Naming convention

- Subfolder name = exact slug matching `book_slug` in `questions/qt-{id}/meta.xml`
- Unit files: `chNN_unit_MM.xml` (content), `chNN_unit_MM_exercises.xml` (exercises)
- Chapter files: `chNN.xml` (all units combined)
- `INDEX.md` = regenerated by `scripts/sync_books.py`
- `atoms.json` = generated by `scripts/extract_atoms.py`
- One subfolder per textbook edition
