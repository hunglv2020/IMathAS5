# Skill: write-imathas-x

Single entry point for all IMathAS authoring tasks. The knowledge is organized in **two layers**:

- **Language Layer** — authoritative macro reference. Use the lookup script; never guess function names.
- **Application Layer** — topic guides, golden cases, cheatsheets. User-managed and expandable.

## 🔧 TOOLING

Three scripts, each with a distinct role:

```bash
# 1. LANGUAGE + GOLDEN LAYER — verify macro existence, get signatures, load required libraries,
#    and fetch direct Odoo golden examples with rationale.
#    Reads from resources/imathas_lang.xml (generated by: uv run update_imathas_lang.py)
uv run .agents/skills/write-imathas-x/scripts/lookup_macro_with_goldens.py <macro1> <macro2> ...
# Search by keyword:
uv run .agents/skills/write-imathas-x/scripts/lookup_macro_with_goldens.py -s <keyword>

# 2. APPLICATION LAYER — search golden cases, cheatsheets, and topic guides

# 3. ROBUSTNESS CHECK — audit a completed control.php for NaN risks, fraction/radical enforcement
uv run .agents/skills/write-imathas-x/scripts/check.py <path/to/control.php>
```

## 🗂️ LANGUAGE LAYER — Macro Lookup

**Guessing macro names is PROHIBITED.** Always call `lookup_macro_with_goldens.py` before using any macro.
This script is now the primary lookup entry point. The legacy `lookup_macro.py` has been archived under `scripts/archive/`.

The macro library is organized by category. Use these as keywords for `-s` search:

| Statistics | `mean`, `median`, `variance`, `permutation`, `combination` |
| Matrix | `matrix`, `determinant`, `inverse` |
| Complex | `complex`, `imaginary` |

| Arrays | `array`, `sort`, `push`, `slice` |
| Tables | `showarrays`, `showrecttable`, `horizshowarrays` |
| Graph (2D) | `showplot`, `mergeplots`, `addlabel`, `alttext`, `dot`, `curve` |
| Graph (3D) | `CalcPlot3D`, `plot3d`, `surface`, `spacecurve` |
| Inequalities | `interval`, `inequality`, `sign chart` |
| Radicals | `sqrt`, `root`, `radical` |
| MathExpr | `expression`, `parse`, `evaluate`, `simplify` |

**Mandatory workflow for macros:**
1. Call `lookup_macro_with_goldens.py` on all macros needed.
   It preserves the exact local macro verification while also attaching Odoo-backed golden examples in XML when available.
2. If `❌ MACROS DO NOT EXIST` → do NOT use them; search for alternatives with `-s`.
3. If `⚠️ LIBRARIES NEED TO BE LOADED` → paste `loadlibrary(...)` at top of ZONE 0.
4. Read `📖 USAGE DOCUMENTATION` — follow the exact signature and edge case notes.
5. Check **Optional Arguments** — macros like `makereducedfraction` have arguments that eliminate complex `if-else` blocks.

**Deep lookup behavior:**
- Exact lookup semantics are preserved.
- Input is normalized by trim only. Case must match exactly. Example: `array` is valid, `Array` is treated as missing.
- Fuzzy matching is used only for suggestions when a macro does not exist. It never auto-substitutes.
- If Odoo golden lookup fails, the script still returns XML with the local macro reference plus `<golden_lookup_error>...`.

## ⚠️ CROSS-CUTTING RULES (Apply to Every Task)

These rules apply to **all** `control.php` code. Violating them causes fatal runtime errors.

### 1. IMathAS Is NOT Standard PHP

`control.php` is processed by a **custom restricted IMathAS eval engine**, not a PHP compiler.

| Rule | ❌ Wrong | ✅ Correct |
|---|---|---|
| No `<?php` tag | `<?php $a = rand(1,5);` | `$a = rand(1,5);` |
| No custom functions | `function calc() { ... }` | Write logic inline in ZONE 1/2 |
| No `while` / `do...while` | `while ($a == 0) { ... }` | `{$a = rand(-5,5)} where $a != 0` |
| No `foreach` | `foreach ($arr as $v)` | `for ($i = 0..$n) { $arr[$i] }` |
| No standard `for` loop | `for ($i=0; $i<$n; $i++)` | `for ($i = 0..$n-1)` — precompute bounds |
| Loop bounds must be integers | `for ($i=1..$n-1)` inline | `$k = $n-1; for ($i=1..$k)` |
| Exponents | `pow($a,$b)` or `$a**$b` | `$a ^ $b` |
| No `array_merge` | `array_merge($a,$b)` | Two separate `showplot` + `mergeplots` |
| No `array_rand` | `array_rand($arr)` | `randfrom($arr)` |

### 2. Validate Before Write (MANDATORY for control.php)

Before writing any non-trivial snippet to `control.php`, run:
```bash
uv run .agents/skills/validate-control-syntax/scripts/test_control.py --control '<snippet>'
```
If `errors` is non-empty → fix the snippet, re-validate, **then** write.

### 3. Zone Order in control.php

```
ZONE 0   loadlibrary(...) calls — required libraries only

ZONE 1   Randomization (math only — NO string operations)
         ├─ MathVar:    rand, diffrands, randfrom, randpythag, ...
         ├─ DerivedVar: abs, gcd, ceil, floor, arithmetic from MathVars
         ├─ where guards and domain constraints
         └─ for loops  (precompute bounds: $k = $n-1 before loop header)

ZONE 2   Display Variables (string output only — no math computation here)
         ├─ § 2A  String Assembly
         │        Build display strings using {$var} interpolation ONLY
         │        $expr    = "{$a} x^2 + {$b} x + {$c}"
         │        $Cdisp   = "[[{$C11},{$C12}],[{$C21},{$C22}]]"
         │        NEVER: $a . " x^2"   ← dot concatenation BANNED
         │        NEVER: "$a x^2"       ← bare $var BANNED
         └─ § 2B  String Normalization
                  Apply makexxpretty / makexxprettydisp / makereducedfraction
                  to § 2A vars only
                  $exprdisp = makexxprettydisp("{$a} x^2 + {$b}")
                  Naming convention: _disp or _pretty suffix on normalized vars

ZONE 3   Answer Computation
         Derive answer values from ZONE 1 MathVars/DerivedVars

ZONE 4   $anstypes[i], $answer[i], $questions[i] arrays
         $answer[i] holds raw grading value — NOT a display string

ZONE 5   Grading config
         $variables[i], $domain[i], $requiretimes[i], $abstolerance[i], $showanswer[i]
```

### 3.5 Interpolation Convention (MANDATORY)

All string assembly in ZONE 2§2A uses `{$var}` brace wrapping exclusively.

| Form | Status |
|---|---|
| `"{$a} x^2 + {$b}"` | **CORRECT** |
| `$a . " x^2 + " . $b` | **BANNED** — dot concatenation |
| `"$a x^2 + $b"` | **BANNED** — bare `$var` |

**Exception:** `$answer[i]` is a raw numeric expression — no braces: `$answer[0] = $y1;`

## WHEN / WHEN NOT to Use This Skill

### Use this skill when:
- Translating a blueprint and static files into a complete `questions/qt-{id}/imathas/` package (Mode A)
- A user reports an error, display issue, or logic flaw and requests a targeted fix (Mode B)
- Rewriting `solution.txt` and `control.php` from a new blueprint while keeping `question.txt` intact (Mode C)
- Looking up a macro signature before using it in any `control.php` edit

### Do NOT use this skill when:
- The task is to verify mathematical correctness of an already-written template → use `audit-accuracy`
- The task is to check whether the template covers source exercises → use `audit-coverage`
- The task is to review terminology or pedagogical alignment → use `audit-pedagogical`
- The user wants to convert LaTeX files or look up AsciiMath syntax → use `asciimath` first, then return here
- The task is stress-testing variable distributions → use `audit-variable-distribution`
- The task is batch seed pass/fail testing → use `verify-imathas-batch`
