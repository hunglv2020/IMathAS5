# Solution House Rules — build-solution-artifact

These rules define the repository's active solution-writing contract and must be preserved
in all solutions generated by this skill.

## Structure

- Step-by-step format: each logical step has a plain-text header starting with a
  strong verb (e.g., "Step 1: Compute the derivative")
- No markdown bold or italic formatting on headers or labels
- Each step: one assertion sentence (WHY) followed by LaTeX computation (WHAT)
- Answer labels match the question's part structure: `Answer to (a):`, `Answer to (b):`,
  or `Final answer:` if the question has no named parts
- Use `$$ $$` for ALL math — inline and display alike
- Never use `$ $`, `\(...\)`, or `\[...\]`
- Every `$$ $$` block must stay on one line; no standalone delimiters

## Recall and citation

- Recall by concept name + sourced statement, not bare theorem numbers
- Do not write `By Theorem 8` or `By Definition 2` — these are opaque to students
- Do not write `Recall from Section 4.4` or similar section-number citations in the
  student-facing solution
- State the sourced content actually used, then apply it
- Keep recall and its immediate application in the same step by default
- Split into a separate step only when recall needs its own pedagogical pause

## Prose

- No decorative prose
- No uncontrolled drift from the mathematical argument
- Assertion sentence should name the operation, property, or theorem being applied
- Do not freely paraphrase sourced theorem statements; only notation-level
  specialization is allowed after the sourced statement is given

## Method

- Preserve the method identified in the recall triage / exercise analysis
- Do not switch methods unless a genuine correction is required
- If `source_brief.xml` specifies a method, treat it as a hint (not authority)
- The current unit's textbook content is always the ground truth for method choice
